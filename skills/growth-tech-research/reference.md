# 分册扩展与数据纪律（Growth Tech Research）

写分册与合订前先读本文件。主流程与估值路由以 `SKILL.md` 为准；此处规定**如何写厚、如何不造假、如何落盘**。

## 1. 扩展原则（加深 ≠ 编造）

| 允许的「加厚」 | 禁止 |
|----------------|------|
| 把 Step 已要求的表写全、多写解读与因果 | 编造营收、净利、市占、PE/PS、管线峰值销售、临床成功率 |
| 增加已抓取/已检索到的行与事件 | 用「大概」「应该是」冒充精确数 |
| 引用研报/公告原文要点并注明出处 | 虚构客户份额、试验结果或未检索新闻 |
| 标明口径差异、估算区间与不确定性 | 用同业「感觉」填本公司空缺；无数据硬套海外 SaaS 单位经济 |
| 数据缺失写「未取得 / 未见 / 待财报」 | 为凑篇幅编故事；把主题投资口吻当结论 |

**铁律：** 每个关键数字须能回溯 `data/`、公开链接，或标注「估算 + 依据」。无法回溯则删除该数字。

## 2. 文件夹与命名

```text
reports/{代码}-{简称}/
  00-总览.md
  01-投资摘要.md
  02-生意模式与财务画像.md
  03-近1-2年重大变化.md
  04-行业空间与竞争格局.md
  05-护城河与能力壁垒.md
  06-管理层·研发组织·资本配置.md
  07-成长路径与产品空间.md
  08-现阶段估值.md
  09-市场看法如何演变.md
  10-近期大涨大跌归因.md
  11-综合判断与跟踪清单.md
  {简称}-投研报告.md
  data/
    research_raw.json
    fetch_log.md
```

- `{代码}` 如 `688981`；`{简称}` 避免空格与特殊符号。  
- 不同股票不得混文件夹；与价值/平台报告共用 `reports/`，靠总览「框架」字段区分。  
- 中间文件一律进 `data/`。

## 3. `00-总览.md`（索引 + 各章浓缩）

必须含：

1. 元信息：财务时点、催化检索时点、**框架 `growth-tech-research`**、**估值路由（A/B/双轨）**、免责声明  
2. 一句话匹配判断  
3. 关键指标小表（市值、收入增速、利润或亏损、PE/PS、路由）+ **≥1 张图**  
4. 链到 `{简称}-投研报告.md`  
5. **各章浓缩**：对应 `01`～`11`；每章 **一句结论 + 关键数字表**（或一张总表）；禁止十一段散文  
6. **一级目录**：只链 `01`～`11` 与合订；不链分册内 `###`  
7. `data/` 主文件说明一句  

总览不要粘贴十一章全文；也不要只剩目录而无浓缩。

### 3.1 `{简称}-投研报告.md`（默认必交）

十一章逻辑收成一篇可独立阅读的报告。排版：**图 → 表 → 短结论**。

| 要 | 不要 |
|----|------|
| 十一章逻辑齐全；估值路由与判定过程写清 | 只有一句话 + 指标表 |
| 财务、空间桥、份额、预测、估值、催化、跟踪能成表则表 | 同一串数字改成散文 |
| **至少 3 张图**（Mermaid） | 通篇无图 |
| 数字与分册同数 | 新造分册没有的结论或目标价 |
| 表/图下 1 句读法 | 合并分册全文 |

### 3.2 建议出图清单（有数据才画）

| 图 | 优先放在 |
|----|----------|
| 营收、利润或亏损（年或近 8 期） | 总览；合订「财务画像」 |
| 份额或产品结构条形 | 合订「竞争/护城河」 |
| 估值路径（PE 或 PS 或股价阶段） | 合订「估值」或「涨跌」 |
| 成长桥或叙事阶段（flowchart） | 合订「成长」或「市场看法」 |

Mermaid：**只用 `xychart-beta` 与 `flowchart`**；不要用 `timeline` / `pie`。`xychart` 禁止负数；轴标签加引号。Canvas 不能替代文内图。

## 4. 分册共通页眉

```markdown
# {N}. {章名}｜{公司名}（{代码}）

> 本分册对应框架 Step {x}。财务时点 {date_fin}；催化时点 {date_cat}（若相关）。  
> 框架 growth-tech-research。数据见 `../data/`。不构成投资建议。
```

文末可加上一分册 / 下一分册 / 回总览链接。

## 5. 各分册如何加厚

结构对齐 `SKILL.md` 对应 Step 小节；有数据才写，无则标明缺口。

| 分册 | 加厚重点 |
|------|----------|
| 01 摘要 | 指标表完整；3～5 条要点点名主矛盾与估值路由；不新造结论 |
| 02 生意与财务 | 生意模式写透；**分部表**；4～8 期合并表；研发/销售费用率；现金与 runway 算式可见；强项/隐患各≥2 |
| 03 变化 | 时间线≥5 条尽量带日期；周期 vs 结构逐条；商业化/监管/融资拐点单列 |
| 04 行业与竞争 | 空间数字或明确缺口+来源；CR/市占年份口径；对手表；政策硬约束 |
| 05 护城河 | 五力每力有证据；定量同业表（按盈利状态选指标）；变薄路径含可指名事实 |
| 06 管理层研发资本 | 转化证据（管线/产品/客户导入）；融资与稀释表或定性；非仅履历 |
| 07 成长与产品 | **空间桥表**；T+1～T+3 情景表；一致预期对照；乐观/中性/悲观触发；行业检查清单按需 |
| 08 估值 | **路由判定过程写清**；A：Forward PE+PEG 算式；B：PS+路径回推表；同业相对 |
| 09 看法 | 叙事阶段；证据表（研报/一致预期/公告/客户侧）；卖方 vs 定价；预期差 |
| 10 涨跌 | **中期 vs 近端分层**；可指名催化表；主因≤3；同业对比 |
| 11 综合 | 回扣 05/07/08/10；前提与风险；可证伪跟踪表加厚 |

分册内部可用 `###`；总览目录仍只列分册文件 + 合订。

## 6. 跨分册一致性

- 价格、市值、PE/PS、增速等以 `data/` 快照为准；总览、分册、合订不得互改。  
- 刷新取数：先 `data/` 与 `00` 指标表，再改分册与合订。  
- Step 10 的客户/管线/竞争结论若成立，须在 `05` 变薄路径有对应表述。  
- Step 8 的 PEG / 路径回推必须引用 `07` 同一套中性假设。

## 7. 与另外两套框架

| | growth-tech-research | value-leader-research | platform-leader-research |
|--|----------------------|------------------------|--------------------------|
| 典型标的 | 半导体、创新药、高成长放量 | 能源电力、稳态制造龙头等 | 成熟主业+颠覆高方差（平台/品牌/IP；A+港股） |
| 估值中心 | 路由：PE/PEG 或 PS/路径 | PE 分位 + **PB-ROE 必做** | **SOTP** + 股东回报 |
| 基本面重心 | 单位经济、费用、runway、稀释 | 杜邦、FCF、资产负债 | 分板块地图、成熟/投入拆分 |
| 分册数量 | `00`～`11` + 合订 | `00`～`09` + 合订 | `00`～`12` + 合订 |

交叉标的：总览必须声明主框架；不要无声明混用尺子。

- [ ] 合订详略中等、≥3 图、能成表已成表；数字与分册一致
