# 分册扩展与数据纪律（Platform Leader Research）

写分册与合订前先读本文件。主流程以 `SKILL.md` 为准。  
本框架关键词：**成熟主业 + 颠覆高方差 + 分板块 + SOTP**；**不限港股、不限互联网**。

## 1. 扩展原则（加深 ≠ 编造）

| 允许的「加厚」 | 禁止 |
|----------------|------|
| 把 Step 已要求的表写全、多写解读与因果 | 编造分部收入/利润、市占、SOTP 倍数、爆款销量 |
| 增加已抓取/已检索到的行与事件 | 用「大概」「应该是」冒充精确数 |
| 引用年报/IR/公告要点并注明出处 | 虚构监管结论、舆情或未检索新闻 |
| 标明口径差异、估算区间与不确定性 | 上市地用错数据源却不标明；用 A 股数冒充港股分部 |
| 数据缺失写「未取得 / 未见 / 待财报」 | 投资收益当经营质量；主题口吻当结论；为凑篇幅编故事 |

**铁律：** 每个关键数字须能回溯 `data/`、公开链接，或标注「估算 + 依据」。无法回溯则删除该数字。

## 2. 文件夹与命名

```text
reports/{代码}-{简称}/
  00-总览.md
  01-投资摘要.md
  02-分板块业务.md
  03-近1-2年重大变化.md
  04-成熟主业分析.md
  05-颠覆与代际风险.md
  06-分板块竞争与护城河.md
  07-治理与资本配置.md
  08-成长情景.md
  09-现阶段估值（SOTP）.md
  10-市场看法如何演变.md
  11-近期大涨大跌归因.md
  12-综合判断与跟踪清单.md
  {简称}-投研报告.md
  data/
    research_raw.json
    fetch_log.md
```

示例：
- `reports/0700-腾讯/`、`reports/9988-阿里巴巴/`（港股平台）
- `reports/603605-珀莱雅/`、`reports/688363-巨子生物/`（A 股品牌）
- `reports/9992-泡泡玛特/`（港股 IP/潮玩）

与另外两套报告共用 `reports/`；总览用框架字段区分。不同股票不得混文件夹。

## 3. `00-总览.md`（索引 + 各章浓缩）

必须含：

1. 元信息：代码、**上市地 A/HK**、财务时点、催化时点、**框架 `platform-leader-research`**、免责声明  
2. 一句话匹配判断  
3. 关键指标表（市值、板块结构摘要、PE、FCF/回购、SOTP 合计 vs 市值）+ **≥1 张图**  
4. 链到 `{简称}-投研报告.md`  
5. **各章浓缩**：对应 `01`～`12`；每章 **一句结论 + 关键数字表**；禁止十二段散文  
6. **一级目录**：只链分册与合订；不链分册内 `###`  
7. `data/` 说明一句  

### 3.1 `{简称}-投研报告.md`（默认必交）

十二章逻辑收成一篇可独立阅读的报告。排版：**图 → 表 → 短结论**。

| 要 | 不要 |
|----|------|
| 十二章逻辑齐全；SOTP 与颠覆敞口写清 | 只有一句话 + 指标表 |
| 分板块、成熟主业、攻击面、情景、估值、催化、跟踪能成表则表 | 同一串数字改成散文 |
| **至少 3 张图**（Mermaid） | 通篇无图 |
| 数字与分册同数 | 新造结论或目标价 |
| 表/图下 1 句读法 | 合并分册全文 |

### 3.2 建议出图清单（有数据才画）

| 图 | 优先放在 |
|----|----------|
| 分板块收入/利润结构（条形） | 总览 / 合订 02 |
| 成熟主业利润路径 | 合订 04 |
| SOTP 堆叠或对照市值 | 合订 09 |
| 颠覆攻击面或叙事 flowchart | 合订 05 / 10 |
| 股价或估值阶段路径 | 合订 11 |

Mermaid：**只用 `xychart-beta` 与 `flowchart`**；不用 `timeline`/`pie`；`xychart` 禁止负数；轴标签加引号。Canvas 不能替代文内图。

## 4. 分册共通页眉

```markdown
# {N}. {章名}｜{公司名}（{代码}）

> 本分册对应 Step {x}。上市地 {A|HK}。财务时点 {date_fin}；催化时点 {date_cat}（若相关）。  
> 框架 platform-leader-research。数据见 `../data/`。不构成投资建议。
```

文末可加上一分册 / 下一分册 / 回总览链接。

## 5. 各分册如何加厚

结构对齐 `SKILL.md` 对应 Step；有数据才写，无则标明缺口。

| 分册 | 加厚重点 |
|------|----------|
| 01 摘要 | 指标表完整；点名主矛盾、颠覆敞口与 SOTP；不新造结论 |
| 02 分板块 | **分板块硬表**完整；产品线/品牌拆分；GAAP/Non-GAAP 或扣非说明；投资收益单列；4～8 期合并摘要；强项/隐患各≥2 |
| 03 变化 | 时间线≥5 条尽量带日期；周期 vs 结构；渠道/爆款/组织/回购/监管单列 |
| 04 成熟主业 | 1～3 个成熟板块各写透；中低速假设有依据；现金流与提效 |
| 05 颠覆 | 攻击面表≥3 条尽量可指名；时间尺度与利润冲击路径；敞口等级；禁止空话 |
| 06 护城河 | **分板块**护城河表；对手与烈度；变薄路径对接 05；能做则加利润率同业 |
| 07 治理资本 | 回购/分红尽量量化；战投与组织阶段；治理红旗有则写 |
| 08 成长情景 | 主业/过渡/新业务（新品牌/新 IP）拆分表；一致预期对照；乐观/中性/悲观触发 |
| 09 估值 | **完整 SOTP 表**（或主业+期权）；股东回报；前瞻 PE；回答贵在主业还是期权 |
| 10 看法 | 叙事阶段；证据表；卖方 vs 定价；预期差（主业 vs 新业务） |
| 11 涨跌 | **中期 vs 近端分层**；可指名催化表；主因≤3；同业对比 |
| 12 综合 | 回扣 04/05/06/08/09/11；前提与风险；可证伪跟踪（分板块 KPI）加厚 |

## 6. 跨分册一致性

- 市值、板块数字、倍数以 `data/` 与年报摘录为准；总览、分册、合订不得互改。  
- 刷新取数：先 `data/` 与 `00`，再改分册与合订。  
- Step 9 SOTP 板块划分须与 `02` 一致（可合并过小板块，须注明）。  
- Step 11 的竞争/监管/爆款主因须在 `05`/`06` 有对应表述。  
- Step 8 中性假设与 Step 9 倍数逻辑一致。

## 7. 与另外两套框架

| | platform-leader | value-leader | growth-tech |
|--|-----------------|--------------|-------------|
| 核心问题 | 成熟现金牛 × 颠覆方差 × 分板块 SOTP | 稳态质量 × PB-ROE | 空间路径 × 成长估值 |
| 市场 | **A 股 + 港股** | A 股为主 | A 股为主 |
| 例子 | 腾讯/珀莱雅/泡泡玛特 | 大唐发电等 | 半导体/创新药等高成长 |
| 特有章 | **颠覆与代际** | PB-ROE | 估值 A/B 路由 |
| 分册 | `00`～`12` + 合订 | `00`～`09` + 合订 | `00`～`11` + 合订 |

交叉标的：总览必须声明主框架；不要无声明混用 PB-ROE、纯成长 PEG 与 SOTP。

## 8. 交付检查（分册专用）

- [ ] 文件夹 `{代码}-{简称}`；存在 `00`～`12` + 合订 + `data/`  
- [ ] 总览含上市地、框架名、各章浓缩（表/图为主）、≥1 图；目录仅一级  
- [ ] 合订详略中等、≥3 图、含 SOTP 表；数字与分册一致  
- [ ] 无无法溯源的关键数字；缺口已标明
