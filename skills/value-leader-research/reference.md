# 分册扩展与数据纪律（Value Leader Research）

写完各章分册前先读本文件。主流程与九步框架仍以 `SKILL.md` 为准；此处规定**如何写厚、如何不造假、文件如何落盘**。

## 1. 扩展原则（加深 ≠ 编造）

| 允许的「加厚」 | 禁止 |
|----------------|------|
| 把 Step 已要求的表写全、多写解读与因果 | 编造营收、净利、市占、PE、目标价 |
| 增加已抓取/已检索到的行与事件 | 用「大概」「应该是」冒充精确数 |
| 引用研报/公告原文要点并注明出处 | 虚构客户份额百分比或未检索到的新闻 |
| 标明口径差异、估算区间与不确定性 | 用同业「感觉」填本公司空缺指标 |
| 数据缺失时写「未取得 / 未见 / 待三季报」 | 为凑篇幅编故事或编对话 |

**铁律：** 每个关键数字须能回溯到 `data/` 中的抓取结果、公开网页/公告链接，或明确标注为「估算 + 依据」。无法回溯则删除该数字，改写「未取得」。

## 2. 文件夹与命名

```text
reports/{代码}-{简称}/
  00-总览.md
  01-投资摘要.md
  02-基本面.md
  03-近1-2年重大变化.md
  04-竞争格局与护城河.md
  05-成长性预测.md
  06-现阶段估值.md
  07-市场看法如何演变.md
  08-近期大涨大跌归因.md
  09-综合判断与跟踪清单.md
  {简称}-投研报告.md     # 默认必交：九章合订、详略中等
  data/
    research_raw.json    # 或按源拆分的多个 json
    fetch_log.md         # 可选：取数时点、接口、失败项
```

- `{代码}`：如 `300750`；`{简称}`：如 `宁德时代`（避免空格与特殊符号）。
- **禁止**把不同股票的报告混在同一文件夹。
- 中间文件（原始 JSON、新闻摘录、估值序列）一律进 `data/`，不要散落在仓库根目录。

## 3. `00-总览.md`（索引 + 各章浓缩）

必须含：

1. 元信息：财务时点、催化检索时点、框架版本、免责声明  
2. 一句话匹配判断  
3. 关键指标小表（与各分册同一套数）+ **≥1 张图**  
4. 链到 `{简称}-投研报告.md` 一句  
5. **各章浓缩**：对应 `01`～`09`。每章 **一句结论 + 关键数字表（或合并成一张九章总表）**，并链到分册。总览另须 **≥1 张 Mermaid 图**（营收/利润、份额或估值路径）。浓缩不是空目录，不是九段散文，也不是把分册全文粘贴。  
6. **一级目录**：只链到 `01`～`09`（及合订报告）；不要链到各文件内部的 `###`  
7. `data/` 说明一句（主数据文件名）

总览**不要**重复粘贴九章全文；**也不要**只剩目录而无浓缩；**更不要**用大段文字代替已经抓到的表和图。

## 3.1 `{简称}-投研报告.md`（单独投研报告，默认必交）

把九章收成**一篇可独立阅读**的报告，给不想点开九个分册的读者。排版：**图 → 表 → 短结论**。

| 要 | 不要 |
|----|------|
| 九章逻辑齐全；每章有结论句 | 只写一句话判断 + 指标表就结束 |
| 财务、同业、份额、预测、估值、催化、跟踪 **凡能成表必须成表** | 把同一串数字改写成散文 |
| **至少 3 张图**（Mermaid：柱/折线、饼图、时间线等） | 通篇无图 |
| 关键数字与分册同数 | 新造分册里没有的数字或结论 |
| 表/图下用 1 句读法 | 把 `01`～`09` 全文合并；或为凑字数把表拆回段落 |

建议结构与分册同序。分册仍是证据主件；合订是「扫读就能讲清楚这门生意」的版本。

### 3.2 建议出图清单（有数据才画，禁止编造）

| 图 | 优先放在 |
|----|----------|
| 营收、归母净利（年或近 8 期）柱状/折线 | 总览 1 张；合订「基本面」或「摘要」 |
| 全球或国内份额饼图 / 条形 | 合订「护城河」；总览可复用 |
| 股价或 PE TTM 路径（阶段高点→当前） | 合订「涨跌归因」或「估值」 |
| 近 1–2 年转折时间线 | 合订「重大变化」或「市场看法」 |

Canvas 可作为交互补充，**不能替代**上述 Markdown 内图。

## 4. 分册共通页眉

每个 `01`～`09` 文件开头建议：

```markdown
# {N}. {章名}｜{公司名}（{代码}）

> 本分册对应框架 Step {x}。财务时点 {date_fin}；催化时点 {date_cat}（若本章相关）。  
> 数据来源见 `../data/`。不构成投资建议。
```

文末可加「上一分册 / 下一分册 / 回总览」相对链接。

## 5. 各分册写什么、如何加厚

结构仍对齐 `SKILL.md` 中 Step 2～9 的小节标题；**加厚方式如下**（有数据才写，无则标明缺口）。

| 分册 | 加厚重点 |
|------|----------|
| 01 摘要 | 指标表完整；3～5 条要点须点名主矛盾；指向后文分册，不新造结论 |
| 02 基本面 | 生意模式一段写透；**分部收入/利润/增速表（年报口径，禁止用装机代替）**；4～8 期合并财务表；杜邦与 FCF 算式可见；营运资本逐项解释；强项/隐患各≥2 条 |
| 03 变化 | 时间线≥5 条尽量带日期与财务印证；周期 vs 结构逐条标注；资本配置变化单列 |
| 04 护城河 | 集中度/市占尽量给年来源；五力每力有证据句；同业利润率/ROE 表；变薄路径含近端可指名事实 |
| 05 成长 | 行业量价与产能；公司 T+1～T+3 增速表；与一致预期对照；乐观/中性/悲观触发条件 |
| 06 估值 | 历史分位表；Forward/PEG；**完整 PB-ROE 计算过程**；同业相对 |
| 07 看法 | 叙事阶段；证据表（研报/一致预期/公告/**客户侧**）；卖方 vs 定价；预期差 |
| 08 涨跌 | **中期 vs 近端分层**；可指名催化表；主因≤3；同业对比 |
| 09 综合 | 回扣 04/05/06/08；前提与风险；可证伪跟踪表加厚 |

分册内部可用 `###` 小节；**总览目录仍只列九个分册文件（外加合订报告链接）**。总览「各章浓缩」用短结论 + 表/图，不要展开成二级目录，也不要九段散文。

## 6. 跨分册一致性

- 价格、市值、PE/PB、EPS、增速等：**以 `data/` 快照为准**，各分册、总览浓缩与合订报告不得互相改数。  
- 若后取数刷新，先更新 `data/` 与 `00-总览` 指标表，再改相关分册与 `{简称}-投研报告.md`。  
- Step 8 的客户/竞争结论若成立，必须在 `04` 变薄路径中有对应表述。

## 7. 交付检查（分册专用）

- [ ] 文件夹命名符合 `{代码}-{简称}`  
- [ ] 存在 `00`～`09` 共 10 个 md + `{简称}-投研报告.md` + `data/` 至少一份原始数据  
- [ ] 总览含各章浓缩（表/图为主）且 ≥1 张图；目录仅一级、链接可点到分册与合订报告  
- [ ] 合订报告详略中等、≥3 张图、能成表的已成表，数字与分册一致  
- [ ] 无「无法溯源」的关键数字；缺口已标明
